# Orchestrator

The orchestrator drives experiment sweeps as a containerised service. It coordinates config pushes to nodes, sends dataset batches through the pipeline, collects results, and emits metrics. It runs as a Docker Compose service or a Kubernetes Job generated by the deploy tool — it is not run manually on the host.

Three orchestrator modes cover different experiment types:

| Mode | Entry point | Config source |
|------|-------------|---------------|
| Single-model sweep | `runner.py` | `experiments/<name>/experiment.yaml` |
| Multi-model sweep | `multi_runner.py` | `experiments/multi/<name>/experiment.yaml` |
| Optimizer experiment | `opt_runner.py` | `experiments/opt/<name>/experiment.yaml` |

## Components

| Module | Role |
|--------|------|
| `framework/nodes/orchestrator/runner.py` | Single-model sweep loop and CLI entry point |
| `framework/nodes/orchestrator/controller.py` | Pushes compression configs to nodes; waits for drain |
| `framework/nodes/orchestrator/data_client.py` | Callback server, batch sending, result collection (image models) |
| `framework/nodes/orchestrator/llama_data_client.py` | Data client for Llama — tokenizes text, decodes logits as perplexity or accuracy |
| `framework/nodes/orchestrator/datasets.py` | Dataset loaders (image models) |
| `framework/nodes/orchestrator/multi_controller.py` | Per-pipeline config push; multi-node health and idle polling |
| `framework/nodes/orchestrator/multi_runner.py` | Multi-model sweep loop, concurrent workload submission, result collection |
| `framework/nodes/orchestrator/opt_runner.py` | Optimizer experiment runner — slot loop, profiling, accuracy model, adapter interface |

## CLI

```bash
python -m framework.nodes.orchestrator.runner \
    experiments/resnet56_equal-split_linear-3_100mbps \
    --callback-host orchestrator \
    --callback-port 8080
```

| Flag | Default | Description |
|------|---------|-------------|
| `--callback-host` | `localhost` / `CALLBACK_HOST` | Hostname nodes use to reach the result callback |
| `--callback-port` | `8080` / `CALLBACK_PORT` | Callback server port |
| `--result-timeout` | `300.0` | Per-batch result wait timeout (seconds) |
| `--dry-run` | — | Print sweep plan without executing |
| `--resume` | — | Skip runs that already have results in the metrics server (default when deployed) |
| `--node-host` | `NODE_HOST` env | Override hostname for all nodes |
| `--metrics-host` | `METRICS_HOST` env | Override metrics server hostname |

## Sweep Loop

For generated experiments (produced by `tools/generate.py`), the runner iterates sub-experiments sequentially. Each sub-experiment resolves its own sweep and runs all its runs before moving to the next sub-experiment. All sub-experiment runs write to the same metrics directory (`metrics_data/<experiment_name>/`), differentiated by run ID.

For each resolved run:

1. **Push config** — controller sends `POST /config` to the sending and receiving node of each link concurrently. Each node drains in-flight requests before applying.
2. **Run data client** — sends all dataset batches to the first node, bounded by `max_in_flight` semaphore (held until result received).
3. **Collect results** — last node POSTs results to the orchestrator's callback server.
4. **Emit metrics** — `ResultEvent` is emitted for each completed batch and streamed to the metrics server alongside node-side events. Results are stored in `metrics_data/<experiment_id>/result.ndjson`.
5. **Log summary** — top-1 accuracy for image models; perplexity or accuracy for Llama.

The runner selects the appropriate data client automatically based on `exp.model`: any model name starting with `"llama"` (case-insensitive) uses `LlamaDataClient`; all others use `DataClient`.

## Resuming Interrupted Experiments

`--resume` tells the orchestrator to skip runs that already have results in the metrics server. Before executing each run the orchestrator queries the metrics server for an existing result event matching the run ID and experiment name. If one is found the run is skipped and the next run starts immediately.

**`--resume` is baked into the orchestrator command by the deploy tool for both Docker Compose and Kubernetes deployments.** Restarting the orchestrator container/pod after a crash automatically resumes from where it left off — no manual intervention needed.

**Completion signal used per mode:**

| Mode | Signal | Notes |
|------|--------|-------|
| Single-model (`runner.py`) | `ResultEvent` | Emitted per batch — any result for the run ID causes the whole run to be skipped |
| Multi-model (`multi_runner.py`) | `RunThroughputEvent` | Emitted exactly once per completed run — cleaner skip signal |

**Behaviour on error**: if the metrics server is unreachable when the resume check runs, the check returns `False` and the run executes normally — the flag never causes a run to be silently dropped.

**Partial runs**: if a crash happened mid-run, the existing partial results are left in the metrics server and the run is skipped. This is acceptable for the crash-recovery use case; for exact reproducibility, delete the partial results before restarting.

`--resume` is not available on the optimizer runner (`opt_runner.py`). Profiling and accuracy-model phases already cache their outputs as artifact files validated by config hash — see `framework/nodes/orchestrator/artifacts.py`.

## Callback Server

The orchestrator embeds a FastAPI callback server (`POST /result`) that node pods reach to deliver inference results. The server binds to `0.0.0.0` on `CALLBACK_PORT` (default `8080`).

**Docker Compose**: nodes reach the orchestrator by its hostname on the shared pipeline network (`CALLBACK_HOST=orchestrator`).

**Kubernetes**: `CALLBACK_HOST` is injected from the pod's own IP via the Downward API. Nodes reach it directly by pod IP — no Service is needed.

## Controller

`push_run_config(exp, run)` sends configs for all links in a resolved run concurrently:

- Sending node receives `{"direction": "outgoing", "method": "...", "rate": ...}`
- Receiving node receives `{"direction": "incoming", "method": "...", "rate": ...}`

`wait_for_all_idle(exp)` polls all nodes' `GET /status` until `in_flight == 0` on every node. Used before pushing config when extra safety is needed.

## Data Client

`DataClient` manages the result callback server for the full session:

```python
client = DataClient(callback_host="orchestrator", callback_port=8080)
async with client.session():
    for run in runs:
        records = await client.run(exp, run_id, first_node_url, emitter)
```

**Semaphore**: `max_in_flight` batches can be in the pipeline simultaneously. The semaphore is acquired before sending and released only after the result is received — ensuring true end-to-end backpressure.

**Callback server**: FastAPI app running on `callback_port`. The `POST /result` endpoint resolves the pending future for the matching `task_id`.

## Results Storage

Results are stored exclusively in the metrics server as `ResultEvent` events at `metrics_data/<experiment_id>/result.ndjson`. There is no separate local `results/` directory. Each event contains:

```json
{
  "event_type": "result",
  "experiment_id": "resnet56_equal-split_linear-3_100mbps",
  "run_id": "topk-A-B_0.10--topk-B-C_0.10",
  "request_id": "topk-A-B_0.10--topk-B-C_0.10_3_abc123",
  "predicted": [3, 7, 2, 5],
  "actual": [3, 7, 2, 1],
  "timestamp": 1234567890.0
}
```

The analysis tools read from `metrics_data/<experiment_id>/result.ndjson` directly. See [docs/analysis.md](analysis.md).

## Datasets

### Image models

| Name | Class | Notes |
|------|-------|-------|
| `cifar10` | `Cifar10Dataset` | Standard test split, downloads if not present |

`dataset.path` in the experiment config is the path inside the orchestrator container. The deploy tool mounts `--dataset-dir` (host path) at that container path.

To add a new image dataset, subclass `Dataset` in `framework/nodes/orchestrator/datasets.py` and register it in `_REGISTRY`.

### Llama

Llama datasets are handled by `LlamaDataClient` directly (not via `datasets.py`) and selected by `dataset.name` in the experiment config:

| Name | Metric | Source |
|------|--------|--------|
| `wikitext2` | Perplexity | WikiText-2 test split via HuggingFace `datasets` |
| `mmlu` | Accuracy (A/B/C/D) | `cais/mmlu` via HuggingFace `datasets` |

The data client tokenizes inputs using the tokenizer saved by `partition_llama.py` and computes metrics from the logits returned by the last node — no GPU is needed on the orchestrator side.

## Metrics

The runner creates its own `MetricsEmitter` and emits:
- `ResultEvent` — per completed batch (predicted + actual labels)
- `EndToEndLatencyEvent` — wall-clock time from batch sent to result received

These are streamed to the metrics server alongside node-side events.

## Optimizer Experiment Runner (`opt_runner.py`)

The optimizer runner executes adaptive-compression experiments defined by `OptExperimentConfig`. Instead of sweeping a fixed compression grid, it runs a **slot loop**: at each slot it queries the external `Inference_Optimizer` library for per-pipeline compression rates, applies them, runs inference, and feeds observed metrics back to the optimizer.

### CLI

```bash
python -m framework.nodes.orchestrator.opt_runner \
    experiments/opt/resnet56_llama_mmlu_linear-3-multi_100mbps \
    --callback-host orchestrator \
    --callback-port 8080
```

| Flag | Default | Description |
|------|---------|-------------|
| `--callback-host` | `localhost` / `CALLBACK_HOST` | Hostname nodes use to reach the result callback |
| `--callback-port` | `8080` / `CALLBACK_PORT` | Callback server port |
| `--result-timeout` | `300.0` | Per-slot result wait timeout (seconds) |
| `--dry-run` | — | Print sub-experiment plan without executing |
| `--node-host` | `NODE_HOST` env | Override hostname for all nodes |
| `--metrics-host` | `METRICS_HOST` env | Override metrics server hostname |

### Sub-experiment phases

Sub-experiments run sequentially in order. Each type has a distinct execution path:

| Type | Execution |
|------|-----------|
| `profiling` | Runs `profiling_batches` rounds at η=1.0; measures per-node compute latency (τ_i) and activation tensor sizes (a_i). Artifacts reused by later phases. |
| `accuracy_model` | Trains a surrogate A_k(η) by querying the metrics server for existing (η, accuracy) records, then running targeted sweeps if fewer than `min_samples` exist. |
| `no_csi` | Lyapunov-based adaptive optimizer. Runs one independent optimization loop per μ in `mu_sweep`. Uses channel estimate from a configurable estimator (e.g. moving average). |
| `csi_aware` | Closed-form η* from CSI. Uses LCB estimator for a conservative channel capacity estimate. One optimization run. |
| Baselines | Single-task and multi-task fixed policies: `max_compression_*`, `no_compression_*`, `uniform_compression_*`, `myopic_*`, `static_equal_share`, `proportional_resource`, `strict_priority_greedy`, `decoupled_descent`, `queue_proportional`, `historical_average_ce`. |

### Slot loop

For `no_csi` and `csi_aware` sub-experiments, the slot loop:

1. **Collect channel probe** — reads the latest per-link probe samples from the metrics server; converts to a `c_t` capacity vector (bps).
2. **Query optimizer** — calls `adapter.step(slot_id, c_t)` → `(eta_per_pipeline_per_link, infeasible)`.
3. **Infeasibility fallback** — if the optimizer cannot find a feasible assignment, all links fall back to η_max and `OptSlotEvent.infeasible=True` is recorded.
4. **Push config** — calls `push_opt_slot_config` to update per-pipeline compression on all nodes.
5. **Run slot** — submits `slot_batches` inference tasks across all pipelines; collects results and per-pipeline accuracy/throughput.
6. **Observe capacity** — `adapter.observe_capacity(c_t)` (channel state feedback; no-op for direct-CSI adapters).
7. **Update dual** — `adapter.update_dual(slot_id, actual_delays)` (Lyapunov queue update; no-op for CSI-aware adapters).

### Adapter bridge

`framework/optimizer/inference_optimizer_adapter.py` translates between the framework's named-node configs and the external optimizer's integer-indexed `InferenceTask` representation:

- `build_global_order(exp)` — assigns stable integer indices to node names using definition order.
- `build_inference_tasks(...)` — constructs one `InferenceTask` per pipeline with τ, a, η_min dicts keyed by global link index; wires accuracy and gradient callables.
- `build_adapter(sub_exp, ...)` — instantiates the correct external optimizer class and wraps it in one of three concrete adapters (`DirectCsiAdapter`, `EstimatedAdapter`, `DualEstimatedAdapter`).
- `extract_eta_per_pipeline_per_link(...)` — converts the optimizer's integer-indexed output back to `{pipeline_id: {link_id: η}}`.

### Metrics emitted

| Event | Emitted by | Description |
|-------|-----------|-------------|
| `opt_slot` | `opt_runner` | Per-slot: slot ID, η per pipeline per link, infeasible flag, per-pipeline accuracy, channel capacity vector |
| `throughput_constraint` | `opt_runner` | Per-slot: achieved RPS per pipeline vs. target |
| `task_accuracy` | `opt_runner` | Per-task: pipeline ID, predicted vs. actual |
